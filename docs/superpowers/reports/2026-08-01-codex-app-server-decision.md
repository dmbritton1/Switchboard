# Codex app-server production decision

## Scope

This evaluation is bounded to the installed Codex SDK/CLI `0.145.0`. The probe is an isolated research script and is not imported by `src/server.ts`, `src/agents/`, or any production transport. It uses stdio JSONL with the `jsonrpc` field omitted and does not opt into `experimentalApi`, WebSocket transport, dynamic tools, or app/connector tool approvals.

The [official Codex app-server documentation](https://developers.openai.com/codex/app-server/) defines the current wire protocol, while the TypeScript schema generated by the installed `0.145.0` executable is authoritative for the executable evaluated here. That generated schema requires `initialize.params.capabilities: null`, a parameterless `initialized` notification, and `_meta: null` in the declined stable MCP elicitation response.

## Deterministic production decision

**Choose SDK-only.**

The decision is final for this phase, not unresolved. The required live evidence for vendor-thread continuity does not exist, and the local real authentication/initialization/shutdown evaluation could not run because no Codex account is configured. Under the approved decision rules, absence of an authorized paid/live smoke defaults production to SDK-only.

The approval-bridge hybrid is rejected. The prototype does not prove that the SDK and app-server safely share the same vendor thread with one process owner; fixture identifiers cannot supply that proof.

An app-server replacement is not a production candidate. Although the version-matched stable schema and offline fixture gates pass, there is no explicitly authorized non-CI live smoke proving new turn, follow-up, resume, cancellation, and existing vendor-thread continuity. Even if those gates later pass, replacement would require a separate design and implementation plan before any production adapter or transport change.
