# Layout Restructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restructure Switchboard's browser UI into a two-level hierarchy (grid → session with tabs) under one persistent header, per `docs/superpowers/specs/2026-08-01-layout-design.md`.

**Architecture:** `web/index.html` grows a persistent `<header>` and a panel slot; its `#chat` and `#graph` sections merge into one `#session` section with a tab strip. `web/app.js` keeps its single-`render()` shape, but `graphId` folds into `openId` + `tab`, and three pieces of real logic move out to a new DOM-free `web/lib.js` so they can be unit-tested. The server is untouched except for one added static filename and one added snapshot field.

**Tech Stack:** Plain ES modules, no build step. Node's built-in test runner (`node --test`) with `node:assert`. Node ≥ 22.18 runs the TypeScript server directly.

## Global Constraints

- **No framework, no build step, no new dependencies.** `web/` is served as static files by `src/server.ts`; everything is plain ESM.
- **All user- or agent-supplied text goes into the DOM via `textContent` or `append(string)`, never `innerHTML`.** Branch names, repo paths, tool summaries, transcript text and commit subjects are all untrusted. This is an existing invariant in `app.js` — preserve it in every new builder.
- **The server's route surface does not change.** No new endpoints. The two permitted server edits are named explicitly in Tasks 1 and 2.
- **Scheduling's data shape is `Queued` from `docs/superpowers/specs/2026-08-01-scheduling-design.md`:** `{ id, trigger, action, createdAt, state: 'waiting' | 'missed' | 'failed', error }`, where `trigger` is `{ kind: 'at', time }` or `{ kind: 'reset', account }`, and `action` is `{ kind: 'create', repo, branch, account, prompt }`, `{ kind: 'send', sessionId, text }`, or `{ kind: 'resume', sessionId, prompt }`. The snapshot has **no `queue` field yet** — the scheduling work adds it. Every reader here treats it as optional and renders nothing when it is absent.
- **This plan does not build scheduling's picker dialog, its `Run` select, or the ⏱ composer button.** Those belong to the scheduling plan. This plan builds the homes they land in: the header's queue badge and panel, and the card's `waiting for reset` action state.
- **Existing behaviour to preserve verbatim:** the transcript's scroll-only-if-near-bottom logic and `scrolledFor` guard; the `STATUS_THROTTLE_MS` batching of `/status` fetches; the `.card[data-id] > .wt` fresh-lookup on fetch resolution; the create-dialog's `returnValue` consumption; the repo combobox; the notification permission bar; upload and drag-drop.

// DOM-free view logic, imported by app.js and covered by test/ui.test.ts.
// Everything else in app.js is DOM assembly, verified by using it — this file
// is the part with branches worth locking down.

export const ORDER = { 'needs-you': 0, working: 1, done: 2, stopped: 3 };

const MIXED = 'Selected worktrees belong to different repos — pick worktrees from one repo';
const basename = (p) => p.split('/').filter(Boolean).pop() ?? p;

/** Blocked first, then running, then finished — most recently changed first within each. */
export function sortSessions(sessions) {
  return [...sessions].sort(
    (a, b) => ORDER[a.status] - ORDER[b.status] || b.statusSince - a.statusSince,
  );
}

/**
 * Which action a card's single slot gets. `queue` is the scheduling queue from
 * the SSE snapshot; it does not exist until the scheduling work lands, so it
 * defaults to empty and the 'waiting' branch is simply never taken today.
 */
export function cardAction(session, queue = []) {
  if (session.pending) return { kind: 'approve' };
  if (session.status === 'working' || session.status === 'needs-you') return { kind: 'stop' };
  if (session.status === 'stopped') {
    const held = queue.find(
      (q) => q.state === 'waiting'
        && q.trigger?.kind === 'reset'
        && q.action?.kind === 'resume'
        && q.action.sessionId === session.id,
    );
    return held ? { kind: 'waiting', account: held.trigger.account } : { kind: 'resume' };
  }
  return { kind: 'none' };
}

/**
 * Label and button states for the selection bar. The same-repo rule is the
 * authoritative one server-side (selectedRepo() in server.ts) — this is the
 * courtesy that disables the buttons instead of erroring after the click.
 */
export function selectionState(sessions, selected) {
  const chosen = sessions.filter((s) => selected.has(s.id));
  if (!chosen.length) {
    return { count: 0, label: '', merge: { enabled: false, reason: '' }, push: { enabled: false, reason: '' } };
  }
  const repos = new Set(chosen.map((s) => s.repo));
  const mixed = repos.size > 1;
  const busy = chosen.find((s) => s.status === 'working' || s.status === 'needs-you');
  return {
    count: chosen.length,
    label: mixed
      ? `${chosen.length} selected across ${repos.size} repos`
      : `${chosen.length} selected · ${basename(chosen[0].repo)}`,
    merge: {
      enabled: !mixed && !busy,
      reason: mixed ? MIXED : busy ? `"${busy.branch}" is still running — stop it or wait` : '',
    },
    push: { enabled: !mixed, reason: mixed ? MIXED : '' },
  };
}
```

// The scheduling queue rides the SSE snapshot (see the scheduling design), which
// does not carry it yet — so this is written to render nothing until it does,
// rather than guarded at each call site.
const queueItems = () => state.queue ?? [];

function triggerLabel(t) {
  if (t.kind === 'at') return new Date(t.time).toLocaleString();
  return `when ${t.account} resets`;
}

function targetLabel(action) {
  if (action.kind === 'create') return `${action.branch} · new worktree`;
  const s = state.sessions.find((x) => x.id === action.sessionId);
  const branch = s ? s.branch : 'deleted session';
  return action.kind === 'resume' ? `${branch} · resume` : `${branch} · message`;
}

function queueRow(q) {
  const row = document.createElement('div');
  row.className = 'queue-row';

  const when = document.createElement('span');
  when.className = 'queue-when';
  when.textContent = triggerLabel(q.trigger);

  const what = document.createElement('span');
  what.className = 'queue-what';
  what.textContent = targetLabel(q.action);

  const del = document.createElement('button');
  del.type = 'button';
  del.className = 'queue-del';
  del.title = 'Remove from queue';
  del.textContent = '✕';
  del.onclick = () => fire({ cmd: 'unschedule', itemId: q.id });

  row.append(when, what, del);

  // missed and failed items stay in the queue on purpose, so their reason has
  // to be readable here — this is the only place they are ever shown.
  if (q.state !== 'waiting') {
    const why = document.createElement('p');
    why.className = 'queue-why';
    why.textContent = q.state === 'missed'
      ? 'missed — its time passed while Switchboard was not running'
      : `failed — ${q.error ?? 'unknown error'}`;
    row.append(why);
  }
  return row;
}

function queuePanel() {
  const box = document.createElement('div');
  const h = document.createElement('h3');
  h.textContent = 'Scheduled';
  box.append(h, ...queueItems().map(queueRow));
  return box;
}

// The session whose ⋯ menu is open, or null. Same pattern as openId: render()
// reads it, handlers mutate it and re-render.
let menuFor = null;

function menuItem(label, onclick, extra = '') {
  const b = document.createElement('button');
  b.type = 'button';
  b.className = extra;
  b.textContent = label;
  // render() is unconditional here, not left as a side effect of onclick(): Copy
  // worktree path mutates no state and triggers no render of its own, so the
  // stale .menu node was never torn down, and the outside-click closer further
  // down (guarded on `menuFor`, which is already null by then) couldn't help either.
  b.onclick = (e) => { e.stopPropagation(); menuFor = null; onclick(); render(); };
  return b;
}

/**
 * Every per-session control that is not the one contextual action. New
 * per-session features go here, so the card face never grows again.
 */
function overflowMenu(s) {
  const wrap = document.createElement('div');
  wrap.className = 'menu-wrap';

  const btn = document.createElement('button');
  btn.type = 'button';
  btn.className = `menu-btn${menuFor === s.id ? ' open' : ''}`;
  btn.title = 'More';
  btn.textContent = '⋯';
  btn.onclick = (e) => {
    e.stopPropagation();
    menuFor = menuFor === s.id ? null : s.id;
    render();
  };
  wrap.append(btn);
  if (menuFor !== s.id) return wrap;

  const menu = document.createElement('div');
  menu.className = 'menu';
  menu.onclick = (e) => e.stopPropagation();

  // Codex sessions never prompt (approvalPolicy 'never'), so the toggle would
  // be a lie there — shown disabled with the reason, not hidden.
  const auto = document.createElement('label');
  const box = document.createElement('input');
  box.type = 'checkbox';
  box.checked = s.auto;
  box.disabled = s.provider === 'codex';
  auto.title = s.provider === 'codex'
    ? 'Codex never asks for approval — it is sandboxed to its worktree instead'
    : 'Approve every tool call automatically, without asking';

/**
 * The only cross-session element in the session view: another session blocking
 * on an approval while you are reading this one. Answerable in place, because
 * walking back to the grid to click Allow is the whole friction this removes.
 */
function renderInterrupt(current) {
  const blocked = state.sessions
    .filter((s) => s.id !== current.id && s.pending)
    .sort((a, b) => a.statusSince - b.statusSince);
  const box = $('#interrupt');
  box.hidden = !blocked.length;
  if (!blocked.length) return;

  const [first, ...rest] = blocked;
  box.replaceChildren();

  // Branch name and tool summary are both untrusted — the summary is chosen by
  // the agent, transitively by whatever it read while working.
  const line = document.createElement('span');
  line.textContent = `${first.branch} needs you — ${first.pending.tool}: ${first.pending.summary}`;
  box.append(line);

  for (const [label, allow] of [['Allow', true], ['Deny', false]]) {
    const b = document.createElement('button');
    b.type = 'button';
    b.textContent = label;
    b.onclick = () => fire({ cmd: 'decide', id: first.id, allow });
    box.append(b);
  }

  const open = document.createElement('button');
  open.type = 'button';
  open.textContent = 'Open';
  open.onclick = () => openTab(first.id, 'chat');
  box.append(open);

  if (rest.length) {
    const more = document.createElement('button');
    more.type = 'button';
    more.className = 'more';
    more.textContent = `+${rest.length} more`;
    more.onclick = () => { openId = null; render(); };
    box.append(more);
  }
}

let toastTimer = null;

function toast(text) {
  const el = $('#toast');
  el.textContent = text;
  el.hidden = false;
  clearTimeout(toastTimer);
  toastTimer = setTimeout(() => { el.hidden = true; }, 6000);
}

/**
 * Fire-and-forget commands, with the failure made visible. The server already
 * rejects the dangerous cases honestly — a send to a session with no live agent
 * is a 404, a resume on a session that is not stopped is a 409 — but until now
 * the browser showed nothing either way. Callers that surface their own errors
 * (the create dialog, merge, push) keep using send() directly.
 */
async function fire(body) {
  const { ok, data } = await send(body);
  if (!ok) toast(data?.error ?? `${body.cmd} failed`);
}
```
