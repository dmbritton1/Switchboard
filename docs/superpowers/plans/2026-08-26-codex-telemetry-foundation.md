# Codex Telemetry Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship authoritative Codex plan and rate-limit windows—including the
five-hour usage limit—through a reusable account-scoped app-server foundation,
while all Codex sessions and turns remain owned by the existing SDK.

**Architecture:** Keep `@openai/codex-sdk` pinned to `0.145.0`, validate the
telemetry subset of the protocol generated by that exact executable, and run one
long-lived app-server supervisor per Codex account. A provider-neutral in-memory
limit model feeds account meters, account ranking, and reset scheduling. Claude
continues using its current no-turn probe. The scheduler performs a coalesced
authoritative read at a reset boundary before releasing work. No app-server
thread or turn method is available in this release.

**Tech Stack:** Node.js 22.18+, TypeScript executed directly by Node,
`@openai/codex-sdk` 0.145.0, newline-delimited JSON-RPC over stdio, HTTP/SSE,
browser JavaScript, `node:test`.

**Spec:**
[`docs/superpowers/specs/2026-08-11-codex-app-server-parity-design.md`](../specs/2026-08-11-codex-app-server-parity-design.md)

**Official references:** [Codex App Server](https://developers.openai.com/codex/app-server),
[Advanced Configuration](https://developers.openai.com/codex/config-advanced),
[Configuration Reference](https://developers.openai.com/codex/config-reference).
The generated contract from the pinned executable remains authoritative when
online documentation and the installed release differ.

## Scope and supersession

This plan is the complete implementation plan for phase one of the revised
design. It supersedes the first-release sequencing in:

- `docs/superpowers/plans/2026-08-11-codex-app-server-foundation.md`
- `docs/superpowers/plans/2026-08-11-codex-limits-and-cutover.md`

Do not execute either older plan before this one. They assume app-server turn
transport lands before limits and therefore no longer describe the approved
release order. Later work will revise them around the supervisor and contract
created here.

Phase one ends with:

- authoritative Codex account windows and plan names;
- a five-hour headline when Codex reports that as its shortest window;
- provider-neutral account ranking and expanded meter rows;
- one long-lived, reusable app-server process per supported Codex account;
- reset-scheduled work released only after a fresh boundary read;
- an opt-in, no-turn live compatibility smoke check.

Phase one does **not** add app-server threads, turns, approvals, questions,
capability discovery, MCP sidecars, transport selection, typed
`UsageLimitExceeded` handling, or automatic recovery of an SDK-owned Codex
failure.

## Global constraints

- Implement in an isolated worktree created with
  `superpowers:using-git-worktrees`; the primary checkout currently has unrelated
  user edits that must remain untouched.
- Use Node 22.18 or newer.
- Keep `@openai/codex-sdk` pinned exactly to `0.145.0`; do not upgrade as part of
  phase one because its generated schema already contains the required methods.
- Keep every Codex session on the existing SDK adapter. Production telemetry
  code must contain no `thread/*` or `turn/*` request path.
- Keep Codex sandbox fixed to `workspace-write` and approval policy fixed to
  `never`; do not expose either setting.
- Do not write `.codex/config.toml` or mutate any user/project Codex config.
- Launch telemetry with process-local overrides for empty hooks, empty MCP
  servers, and disabled OTel export. If the pinned executable or generated
  contract cannot establish side-effect-free no-turn startup, mark telemetry
  unavailable and keep the local estimate.
- Never refresh auth. `account/read` must use `{ refreshToken: false }`.
- Never persist provider snapshots. Never log, persist, return over SSE, or
  render account environment values, raw stderr, auth data, or absolute paths.
- Keep `npm test` offline. All automated app-server tests use the fake process;
  the installed-account smoke check is a separate manual command.
- Preserve existing Claude rate-limit events and Claude automatic requeue
  behavior. Do not broaden that heuristic to Codex snapshots or SDK errors.
- Run focused tests after each red/green cycle and `npm test` before completion.
- Commit only files named by the active task. Do not include unrelated dirty
  files in any task commit.

  reports a five-hour window.

## Rollback boundary

The phase-one rollback is limited to disabling coordinator startup and removing
the provider snapshots from SSE. Because sessions remain SDK-owned and no
transport field is added, rollback requires no session migration or persisted
state rewrite. Existing local pace, Claude limit probing, Claude rejected-event
requeue, and all SDK Codex behavior remain available.
